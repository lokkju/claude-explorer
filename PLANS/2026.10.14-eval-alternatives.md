# claude-explorer: alternatives survey (2026-10-14)

> Survey of existing tools that could replace claude-explorer, written 2026-10-14.
> The direction chosen afterwards was to build on a fork of kenn-io/agentsview, [lokkju/agentsview](https://github.com/lokkju/agentsview), instead of extending claude-explorer.

All repository figures (stars, last push, latest release, license) come from the GitHub API on 2026-10-14. Feature claims come from each project's README or docs on `main` as of that date; where I read source code to settle a claim, the file is named.

## A fact that changes the premise

The upstream, [rpeck/claude-explorer](https://github.com/rpeck/claude-explorer) (Apache-2.0, 17 stars), is not unmaintained as of this week. It had 291 commits in May 2026, 3 in July, then 44 in September and 19 so far in October, with releases v1.1.1, v1.1.2 and v1.1.3 all published on 2026-10-13. What it does not do is take outside work: your four PRs ([rpeck/claude-explorer#2](https://github.com/rpeck/claude-explorer/issues/2), #3, #4, [#5](https://github.com/rpeck/claude-explorer/issues/5)) sat from July with CLA signed, your 2026-10-01 ping to @rpeck went unanswered, and you closed them yourself at 03:44 UTC today. `lokkju/claude-explorer` is 72 commits ahead and 66 behind upstream. So the situation is a single-maintainer upstream that ships but doesn't review, and a fork diverging from it in both directions; the cost of keeping the fork is rising, not fixed.

## What claude-explorer does today

From its README and FUTURES.md:

- Sources: Claude Desktop / claude.ai chats fetched through the unofficial claude.ai API (cookie captured by Playwright or a proxy), including a rescue path for accounts whose login email is lost; Claude Code JSONL read live from `~/.claude/projects`; Cowork sessions read live from `local-agent-mode-sessions`.
- SQLite FTS5 search (AND tokens, quoted phrases), scoped by source, workspace and filter.
- Export to Markdown, PDF (WeasyPrint) and bundle; per-message bookmarks with notes.
- Message-tree visualization for branched claude.ai conversations.
- Image-cache watcher that preserves `~/.claude/image-cache` before Claude Code rotates it.
- Stdio MCP server (`list_sessions`, `list_projects`, `get_session_outline`, `get_messages`, `export_session`).
- Your fork's additions: `doctor`, `install` (watcher, MCP), scheduled incremental fetch with re-auth alerting.

Desired and not built: multi-machine aggregation on a central server, facets by machine, account, session type and harness (including opencode), faceted search (FUTURES S2), semantic search (FUTURES S1), an in-app assistant over the archive.

## 2. Replace outright, cover parts, and what is lost

**agentsview is the only candidate that could replace claude-explorer outright**, and it already ships most of the desired list: Claude Code, Cowork and claude.ai in one archive; OpenCode and Codex alongside; FTS5 plus semantic and hybrid search; a machine facet built on installation IDs; PostgreSQL aggregation with a read-only server; an HTTP MCP endpoint that can read the shared database; LLM-generated insights and a "recall" corpus against any OpenAI-compatible endpoint. Semantic search against pgvector means the central server can use the homelab's own embedding model through the LLM gateway.

What you'd lose moving to it:

- **Unattended claude.ai fetch.** agentsview's live sync goes through a Chrome extension and native-messaging host in a signed-in Chrome profile (Chrome only; not Chromium, Edge or Brave), with Chrome open during the sync. `agentsview import --type claude-ai --sync` can be scripted, but that's not the headless cookie fetch with re-auth alerting your fork has. The fallback is the official emailed export zip.
- **Branches.** `internal/parser/claude_ai.go` "selects the visible branch" of a claude.ai chat, and drops `tool_use` and `tool_result` blocks in those chats. claude-explorer keeps the whole tree and visualizes it.
- **Account rescue** for a lost login email; nothing else does this.
- **PDF and bundle export.** agentsview exports HTML, Gist, JSON and NDJSON.
- **Image-cache preservation.** I found no equivalent of the image-cache watcher in agentsview's code.
- **Per-message bookmarks with notes.** agentsview has stars, pins, names and trash at session level; I didn't verify message-level notes.
- **Account as a facet.** Machine and agent are first-class; whether claude.ai imports from two accounts stay distinguishable I could not verify from the docs.

**Partial coverage:**

- *Central multi-machine piece:* agentsview `pg push` / `pg serve` is the best fit because it keeps full transcripts. cass does SSH/rsync pull aggregation well but is a TUI with no web UI, and its license rider withholds all rights from Anthropic and anyone acting on Anthropic's behalf, which matters if your use of it ever runs through Anthropic tooling. Langfuse covers it as a trace store with full-text search and user/session filters, but it models turns as traces for observability, not as readable conversations.
- *Native OTel:* Claude Code can now export prompts, assistant responses, tool details, tool output and raw API bodies, tagged with session, account, email and organization. That's a real multi-machine feed with no agent on each host beyond env vars, and Cowork can be configured the same way. It doesn't include claude.ai chats or history from before you turn it on, and the result is event logs, not browsable sessions.
- *Multi-harness viewing alone:* jhlee0409's viewer and codeg both read OpenCode and are healthy, but neither aggregates machines or exposes history over MCP.

## 3. Hybrid options

1. **agentsview for everything except claude.ai fetch; a stripped claude-explorer fetcher feeds it.** Run agentsview on each machine with `pg push` (or the auto-push service) into a Postgres on the home server, and `pg serve` plus `agentsview mcp` over HTTP behind Traefik or Tailscale. Shrink claude-explorer to its fetcher: the headless cookie capture, scheduled incremental fetch and re-auth alerting, writing claude.ai's `conversations.json` export shape so `agentsview import --type claude-ai` ingests it. That sheds the UI, search, MCP, exporters and Cowork/Code readers you now maintain alone, and keeps the one part nobody else does.
2. **Contribute upstream to agentsview instead.** The gaps are the kind an active MIT project with 100+ contributors and weekly releases takes: preserve all claude.ai branches, a headless claude.ai sync path (your fetcher's approach as an alternative to the Chrome host), an image-cache preserver, PDF export, an account facet. Whether they'd accept a headless cookie-based fetch is their call; ask in an issue before writing it.
3. **Keep claude-explorer whole, add an OTel collector.** Point every machine's Claude Code at an OTLP endpoint (Langfuse, or the VictoriaMetrics stack you already run) for the cross-machine, cross-harness view, and keep claude-explorer as the local reader. Least migration, but you'd still be building faceted search, semantic search and the assistant yourself, and you'd have two archives that don't join.
4. **Keep the fork and rebase onto upstream.** Upstream shipping again makes this possible, but four PRs ignored for three months says your changes stay a fork, and none of the desired features are on upstream's README.

## 4. Recommendation

Adopt agentsview as the archive, central server and MCP endpoint, and stop developing claude-explorer's UI, search and MCP. Keep only its claude.ai fetcher, reduced to a scheduled job that produces an export agentsview can import, until agentsview has a headless claude.ai path; open an issue there proposing one, and offer branch preservation as the first contribution, since it's the loss that would bother you most. Trial it before committing: install on the home server and one laptop, `pg push` both into a scratch Postgres, import a claude.ai export, and check three things I couldn't verify from docs: that two claude.ai accounts stay distinguishable, how the Cowork parser handles your sessions, and that semantic search works against the gateway's embedding model. Keep the current claude-explorer install running read-only until that passes, since it's the only copy of the branch trees and cached images.

Native Claude Code OTel is worth turning on regardless; it costs a few env vars and gives per-account cost and activity, but it's no substitute for the transcript archive.
